# Requirements completeness and delivery gate

## When to load
A feature, bug fix or agent task is offered as complete.

## Procedure
Map each authorized requirement to changed behavior, acceptance criteria and actual evidence. Inspect placeholder behavior, unreachable branches, false-success results, incomplete error handling, missing integrations and undocumented scope changes. Compare actual implemented capabilities to claims. If a requirement is intentionally deferred, require an approved scope change and ensure no misleading public contract.

## Required evidence and acceptance
Requirement-to-artifact and requirement-to-test mapping; explicit incomplete or unverified items and approval for any changed scope.

## Guardrails
Do not infer completion from comments, scaffolding or a successful build. A coherent partial delivery may be useful but must not pass a required completeness rule.
