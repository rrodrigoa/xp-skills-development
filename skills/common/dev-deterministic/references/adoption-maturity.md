# Maturity and adoption sequencing

## When to load
Scaling an agent team or starting a new project.

## Implementation in the target project
Assess levels per component: documented intent; enforceable boundaries and checks; reliable independent runtime evidence; risk-based formal verification where justified; controlled automation. Select the lowest missing foundation before increasing concurrency. Pilot on one high-value feature and compare defects, review time and cycle cost against baseline. Establish rollback and authority for each expansion.

## Required evidence and acceptance
Level claims cite target artifacts, live checks and independent assessment. Progress requires demonstrated evidence, not a checklist score.

## Guardrails
Do not mandate formal proofs for every component or equate volume of PRs with maturity.
