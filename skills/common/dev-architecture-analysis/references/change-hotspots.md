# Change hotspots and temporal coupling

## When to load
Prioritizing maintenance across repository history.

## Procedure
Choose a declared history window, normalize renames where possible and exclude mechanical bulk changes with rationale. Combine churn or change frequency with complexity, defect history and ownership; inspect files frequently changed together and why.

## Required evidence and acceptance
Report window, commits, counts, exclusions and representative co-change examples with candidate boundaries.

## Guardrails
Correlation is not causation; new or rarely changed safety-critical code can still deserve priority. Do not rank individual developers.
