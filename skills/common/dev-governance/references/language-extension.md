# Adding a language overlay

## When to load
Adding another language or runtime to the skills repository.

## Procedure
Inventory existing common cards before writing new guidance. Classify each proposed topic as language-neutral intent, language-specific implementation, toolchain evidence or project-specific policy. Extend common only for transferable principles. Create a group under skills named for the language and select unique skill identifiers with the language prefix. Keep SKILL.md metadata small, relative links local, and shared references by logical skill/card identifier. Provide design, implementation, testing, delivery and runtime coverage as appropriate, not necessarily a forced one-to-one set. Add routes, install instructions, source links, and mixed-language scenarios; retain the stable gate IDs.

## Review
Check every referenced shared card exists, no canonical patterns or decision protocol are duplicated, installation works as flattened directories, and language assumptions do not leak into other overlays. Include version-dependent features and evidence limitations. Do not add runtime code or executable examples.
